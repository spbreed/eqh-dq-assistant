# CLAUDE.md — EQH AI Data Quality Assistant (pilot)

`SPEC.md` is the source of truth. This file summarises the ground rules (SPEC §B2) and how to work in this repo.

## Ground rules
1. **Credentials:** use `AWS_PROFILE`/`AWS_REGION` (or the short-lived env vars a cloud session injects). Never read,
   print, export or create credentials. Never write secrets to files. On an auth failure, stop and ask the human to
   run `aws sso login --profile eqh-pilot` (or refresh the session's env vars).
2. **Region:** `us-east-1`, read from `config/pilot.yaml` / env. Never hard-code it in code.
3. **IaC only:** every AWS resource is created by the CDK v2 (Python) app in `infra/`. Ad-hoc CLI calls are for
   verification only. (Catalog/data objects created by `datagen` — Glue tables, Redshift DDL — are data, not infra.)
4. **Tag everything:** `project=eqh-dq-assistant`, `env=pilot`, `owner=$EQH_PILOT_OWNER`, `data=synthetic`.
5. **Least privilege:** the harvest role has read-only metadata access; the assistant role can read only the
   metadata store and invoke Bedrock. No `*:*`.
6. **Secrets** live in Secrets Manager only. DB passwords are generated by CDK / RDS and never printed.
7. **PHI guard (simulated):** synthetic data is treated as PHI. The metadata store, prompts and logs hold
   **metadata and aggregate metrics only** — never row values or sample values. `tests/test_phi_guard.py` enforces it.
8. **Verify current APIs before coding** and record findings in `docs/DECISIONS.md`.
9. **Small, testable steps:** each phase ends with passing `pytest` and `scripts/verify_phaseN.sh`.
10. **🛑 checkpoints:** list what will be created and its monthly cost, and get approval before `cdk deploy`,
    `cdk destroy`, or anything billable or irreversible.
11. **Teardown always works:** `make destroy` (typed confirmation) removes everything, including buckets and snapshots.

## Working in this repo
- `source scripts/env.sh` before any command (region, regional endpoints, venv, PYTHONPATH).
- All database access goes through **Data APIs** (`jobs/common/db.py` → RDS Data API for Aurora,
  `jobs/common/redshift.py` → Redshift Data API). No direct TCP to databases is needed, so every job runs the same
  way from a laptop, a cloud session, or a Fargate task.
- LLM calls go through `jobs/common/llm.py` (OpenAI SDK, Responses API on Bedrock). Never send row values to a model.
- Synthetic data only: fictitious payer codes (`PAYER_AZ1`…), no real payer/provider names, no EQH branding.
- `make help` lists targets. Phase checks: `scripts/verify_phase*.sh`.
